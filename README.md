# 工程合约条款检索工具

一个用于**香港工程合约**的小工具：读入合约文件，按条款切分，用关键词快速定位相关条款。

> 起因：在工地实习时发现，找一条合约条款要翻几百页 PDF，或者去问合约经理。
> 这个工具想解决的就是「这条规定到底在哪」这件事。

---

## 功能

- 支持 `.txt` / `.md` / `.pdf` 三种格式
- 自动按「第X条」把合约切分成完整条款
- 关键词检索，返回全部命中的条款原文
- 空格不敏感：搜「千分之一」和「千分之 一」结果一致
- 可以连续查询，输入空行退出

## 运行效果

```

共切出 14 条条款。
请输入关键词（直接回车退出）：

包含「违约金」的条款有 1 条：

--- 第 1 条命中 ---
第四条 违约金 4.1 若承包商未能于第 2.1 条规定的期限内竣工，须按每延误一日
支付合约总额千分之一的违约金。 4.2 违约金累计最高不超过合约总额的百分之十。
4.3 支付违约金后，承包商仍须继续履行完成工程的义务。
```

## 使用方法

```bash
# 1. 安装依赖
pip install pypdf

# 2. 把合约文件放在同一目录
#    sample_contract.pdf 或 sample_contract.txt

# 3. 运行
python contract_search.py
```

## 实现思路

整个流程只有四步，对应四个函数：

```
load_text()      读取文件，按扩展名分流（pdf 用 pypdf，其他按文本读）
      ↓
split_clauses()  把行列表合并成条款：遇到「第X条」开头的行，就开启新条款
      ↓
search()         逐个条款比对关键词，收集命中的条款
      ↓
main()           串起上面三步，处理用户输入与输出
```

### 两个关键设计

**1. 按条款边界切分，而不是按固定字数**

如果按「每 400 字切一块」，条款会被从中间切断，检索出来的片段可能从半句话开始。
按「第X条」切分，保证每一块都是一条完整的规定。

**2. 比对口令前先去掉空格**

PDF 提取文字时会在中文词中间插入换行或空格，例如 `千分之一` 可能被提取成
`千分之\n一`。直接比对会漏掉。所以在比对前，关键词和条款都会先去掉空格。

## 已知限制

这个工具还很粗糙，以下都是真实存在的问题：

| 限制 | 影响 | 可能的改进方向 |
|---|---|---|
| 只能精确匹配关键词 | 问「拖久了要赔钱吗」搜不到「违约金」条款 | 换成向量检索，用语义相似度匹配 |
| PDF 提取会插入空格/换行 | 已用去空格缓解，但极端情况下仍会漏 | 更完善的文本清洗 |
| 扫描件 PDF 无法提取文字 | 图片型 PDF 读出来是空的 | 需要 OCR |
| 条款切分依赖「第X条」格式 | 格式不同的合约（如 clause 1.1）会切错 | 支持多种条款编号格式 |
| 表格类条款处理不了 | 工程量清单、付款表读出来是乱的 | 表格识别 |
| 只能检索，不能回答 | 用户还要自己读条款原文 | 接入大模型，直接给答案并标注出处 |

### 调试中发现的问题

记录下来，供以后参考：

1. **PDF 提取会在词中间插换行** —— 搜「千分之一」在 txt 版本能找到，
   在 PDF 版本返回 0 条。原因是提取结果是 `千分之\n一的违约金`。
   修复方式：比对前双方都去掉空格。

2. **字符串方法不改变原值** —— 写 `keyword.replace(" ", "")` 而没有赋值，
   结果被丢弃。字符串是不可变的，必须接住返回值。

3. **中文标点与英文标点的混用** —— 输出里曾出现英文逗号，看着不专业。
